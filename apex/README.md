# نسخة Oracle APEX — نظام مهام الدعم الفني والصيانة

نسخة تجريبية من النظام تعمل على **Oracle APEX** بدل Supabase، بنفس الواجهة والتصميم والصلاحيات.
لا تؤثر على نسخة Supabase (الموقع الحالي) بأي شكل: كل ملفاتها داخل هذا المجلد.

## كيف تعمل

| الجزء | في Supabase | في APEX |
|---|---|---|
| الواجهة | ملفات `css/` و `js/` و `fonts/` | **نفس الملفات** محفوظة داخل التطبيق (Static Application Files) |
| قاعدة البيانات | PostgreSQL، سكيما `support_tasks` | Oracle، جداول تبدأ بـ `ST_` |
| الصلاحيات والقواعد | RLS + دوال + مشغّلات | حزمة `ST_API` + مشغّلان |
| الدخول | دالة `auth-login` | مصادقة APEX مخصصة (`st_api.authenticate`) |
| المحوّل | `js/data/supabase/` | `apex/web/js/data/apex/` |

كل طلب من الواجهة يمر بعملية APEX واحدة اسمها `API` تستدعي `st_api.ajax`، فتحدد المستخدم من جلسة APEX وتفحص صلاحيته.

## الملفات

```
apex/
├── sql/
│   ├── 01_schema.sql       الجداول والفهارس والعرض st_v_tasks
│   ├── 02_api.sql          حزمة ST_API والمشغّلان (كل المنطق والصلاحيات)
│   ├── 03_seed.sql         القيم الأولية للقوائم والإعدادات
│   ├── 04_first_admin.sql  أول مدير للنظام (مرة واحدة)
│   └── uninstall.sql       حذف كل الكائنات (لإعادة التركيب من الصفر)
├── web/                    ملفات الواجهة الخاصة بـ APEX (تحل محل نظيراتها عند البناء)
├── tools/build.mjs         يبني ملف التطبيق من الواجهة الحالية
├── build/base_f116280.sql  تصدير التطبيق الفارغ من APEX (أساس البناء)
└── f116280.sql             ملف التطبيق الجاهز للاستيراد (ناتج البناء)
```

## التركيب من الصفر

1. **SQL Workshop ← SQL Scripts** (أو SQL Commands): نفّذ بالترتيب `01_schema.sql` ثم `02_api.sql` ثم `03_seed.sql`.
   تأكد بعد `02_api.sql` من عدم وجود أخطاء:
   ```sql
   select * from user_errors where name like 'ST\_%' escape '\';
   ```
2. افتح `04_first_admin.sql`، اكتب رقمك واسمك في السطرين المعلَّمين بـ ←، ونفّذه. كلمة المرور = نفس الرقم.
   ⚠️ في SQL Commands لا تظلّل أي نص قبل الضغط على Run، فهي تنفّذ النص المظلل فقط.
3. **App Builder ← Import**: اختر `f116280.sql` واستورده (Parsing Schema = سكيما مساحتك).
4. شغّل التطبيق وادخل برقمك.
5. **الإعدادات ← تحديث بيانات التجربة من الإنتاج**: ينقل المستخدمين والقوائم والإعدادات وكل المهام وسجلها من Supabase.
   يطلب رقمك وكلمة مرورك في الإنتاج (للقراءة فقط، لا تُحفظ). كلمات مرور المستخدمين تصبح أرقامهم المدنية/الوظيفية (أو كلمة موحدة)، وحسابك يبقى بكلمة مروره.
   يمكن تكراره متى شئت لأخذ نسخة أحدث من الإنتاج.

## التحديث بعد أي تعديل

- **تعديل على الواجهة** (في `js/` أو `css/` لنسخة Supabase، أو في `apex/web/`):
  ```bash
  node apex/tools/build.mjs
  ```
  ثم App Builder ← Import ← `apex/f116280.sql` ← **Change Application ID** = رقم التطبيق الحالي (20306) ← Replace.
  الرابط لا يتغير، والبيانات في الجداول لا تتأثر.
- **تعديل على `02_api.sql`**: نفّذه مرة أخرى في SQL Workshop (يستبدل الحزمة والمشغّلين، والبيانات لا تتأثر).

إذا تغيّر نص في الشاشات تعدّله أداة البناء (قائمة `PATCHES` في `build.mjs`)، يتوقف البناء برسالة توضح النص المطلوب.

## الرابط الحالي (التجربة)

`https://oracleapex.com/ords/f?p=20306:1` — مساحة `ABDULLAH.ALFURQANI.2024`

## فروق عن نسخة Supabase

- كلمة المرور الافتراضية للمستخدم الجديد = رقمه، و«إلزام تغيير كلمة المرور» مطفأ افتراضياً.
- كلمات المرور مشفّرة في Oracle (SHA-256 مكرر مع salt لكل مستخدم)، ومستقلة عن كلمات مرور Supabase.
- الحماية من التخمين: 8 محاولات خاطئة خلال 15 دقيقة لنفس الرقم توقف الدخول 15 دقيقة.
- «الدخول بحساب مستخدم» ينتهي بعد ساعة كما في Supabase.
- لا يوجد فحص تحديثات تلقائي: APEX يغيّر رابط الملفات مع كل استيراد، فيحصل المتصفح على النسخة الجديدة مباشرة.
- apex.oracle.com للتجربة والتطوير فقط حسب شروط Oracle، وليس للاستخدام الفعلي.
