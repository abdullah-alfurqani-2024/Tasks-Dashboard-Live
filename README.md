# نظام مهام الدعم الفني

نظام ويب لمتابعة مهام قسم الدعم الفني، يحل محل ملفات Google Sheets والسكربتات ولوحة Looker Studio.

- **الواجهة:** HTML وCSS وJavaScript فقط، بدون مكتبات وبدون خطوة بناء. تعمل مباشرة على GitHub Pages.
- **قاعدة البيانات:** Supabase (PostgreSQL)، والصلاحيات مفروضة داخل قاعدة البيانات نفسها (RLS).
- **قابلة للتبديل:** الشاشات لا تعرف أي قاعدة بيانات تعمل خلفها، فيمكن الانتقال لاحقاً إلى قاعدة أخرى بكتابة «محوّل» جديد فقط.
- **مجاني:** الخطة المجانية في Supabase واستضافة GitHub Pages المجانية.

> **وضع تجريبي:** إذا كانت بيانات Supabase فارغة في `js/config.js` يعمل النظام ببيانات وهمية داخل المتصفح. هذا يفيد للتجربة قبل الربط، وتظهر في صفحة الدخول حسابات تجريبية لكل دور.

## التركيب

الخطوات كاملة بالترتيب في **[docs/SETUP.md](docs/SETUP.md)**، وتستغرق نحو 15 دقيقة:

1. تنفيذ ملفات SQL في Supabase.
2. إنشاء أول مدير.
3. نشر دالة إدارة المستخدمين.
4. كتابة الرابط والمفتاح العام في `js/config.js`.
5. تفعيل GitHub Pages.

## هيكل المشروع

```
index.html                 الصفحة الوحيدة (SPA)
css/app.css, print.css     التنسيق والطباعة
js/config.js               الإعدادات (الملف الوحيد الذي يُعدَّل عند التركيب)
js/app.js                  الإطار العام والمسارات وصلاحيات الصفحات
js/core/                   الأدوات المشتركة: DOM، التواريخ، الموجّه، الحالة والصلاحيات، التصدير
js/ui/                     مكونات الواجهة: الجدول، النوافذ، الأيقونات، نموذج المهمة
js/lib/                    zip وxlsx وcsv والرسوم البيانية والإحصاءات (مكتوبة يدوياً بلا مكتبات)
js/pages/                  الشاشات
js/data/contract.js        عقد طبقة البيانات (ما يجب أن يوفّره أي محوّل)
js/data/supabase/          محوّل Supabase (fetch مباشر بدون supabase-js)
js/data/demo/              المحوّل التجريبي داخل المتصفح
supabase/sql/              الجداول والدوال والصلاحيات والبيانات الأولية
supabase/functions/        دالة admin-users لإدارة المستخدمين على الخادم
supabase/tests/            45 اختباراً للصلاحيات على PostgreSQL
```

## تغيير قاعدة البيانات لاحقاً

1. أنشئ مجلداً جديداً داخل `js/data/`، مثل `js/data/firebase/index.js`، يصدّر الدالة `createAdapter(config)`.
2. يجب أن تعيد الدالة نفس الكائنات والدوال الموصوفة في [`js/data/contract.js`](js/data/contract.js).
3. أضفه إلى `ADAPTERS` في [`js/data/index.js`](js/data/index.js)، واكتب اسمه في `CONFIG.backend`.

لا تحتاج أي شاشة للتعديل. المحوّل التجريبي `js/data/demo/` مثال كامل وقصير على ذلك.

**تنبيه:** أي قاعدة بيانات بديلة يجب أن تفرض الصلاحيات على الخادم كما يفعل ملف `03_security.sql`، لأن فحوصات الواجهة للراحة فقط ولا تحمي البيانات.

## الأمان

- المفتاح في `js/config.js` هو المفتاح **العام** (anon أو publishable)، وهو مصمَّم ليكون في المتصفح.
- الحماية الفعلية بسياسات RLS والدوال داخل قاعدة البيانات، وهي مختبرة في `supabase/tests`.
- مفتاح `service_role` لا يوضع في المستودع ولا في المتصفح أبداً. تستخدمه دالة `admin-users` فقط من بيئة Supabase نفسها.
- التسجيل الذاتي مغلق، والمدير وحده يضيف الحسابات.
- الحذف ناعم: المهمة المحذوفة تبقى في قاعدة البيانات ويمكن استعادتها.
- كل تغيير على المهام يُسجَّل تلقائياً في `task_audit`، ولا يستطيع أحد تعديل هذا السجل من الواجهة.
